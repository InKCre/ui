# B3 设计角色与响应契约

状态：B3.1—B3.3 已完成。本文保留 B3 的初始候选；随后授权的 [B4 场景验证](b4-validation.md) 已完成，具体取舍与修订以 B4 记录为准。用户已授权执行 B3；本片交付设计决定、具体候选和实验条件，未修改生产 Token、生成器、组件或消费者。既有行为与处理清单见 [角色盘点](b3-role-inventory.md)，执行边界见 [L1 方案](plan-l1-token-system.md)。

下文“决定”是本片确定的设计责任和约束；“候选”是供 B4 比较的具体默认实现。候选名称采用现有路径的最小扩展，不表示已经成为公开 API。B4 可以依据观察调整数值和必要命名，但不能无说明地改变角色用途、覆盖责任或内容可用性要求。

## 共同决定与默认消费顺序

先使用已有组件和默认组合；需要表达自己的文本或容器时，按用途选择公开角色与基础尺度；局部几何由组件或宿主 CSS 表达。只有存在共同设计决定或稳定配置需求时才增加共享角色。直接数值、固定尺度和断点可以合理存在，采用它们需要对应清楚的用途，而不是仅因同值 Token 存在就被禁止。

默认设置页候选采用 InkForm 的 col 布局、带自身 label/error 的 InkInput，以及明确 nativeType 的提交按钮；页面标题先试 title-lg，普通说明 body-md，字段帮助／错误 body-sm。普通主操作用 primary，危险动作明确使用 danger，处理结果提供文字反馈。宿主负责将自己的普通正文绑定 text.base／surface.base，库不通过全局 reset 强行改写消费者 body 样式。

这次保留 ref 的构建基础、sys 的主题／历史消费入口及确有作用的 comp 角色，不把命名空间等同于强制的三层依赖。`sys.space` 等已有尺度投影有消费兼容与运行时读取责任，但不能仅凭这个前缀宣称它已经表达字段或页面的语义。

新增角色由实际调用支持：普通与辅助正文、介于小标题和醒目大标题之间的页面标题，以及成功／警告／信息反馈。暂不建立完整状态表面矩阵、通用 density、流式排版引擎或跨平台表达式格式。

## T：文本角色、字体与内容尺寸

**T1 决定：** 普通 UI 文本和代码文本采用两个明确的字体来源。候选默认沿用现有 ref 的 system-ui 栈与 mono 栈，通过公开的 `sys.typo.family.sans/mono` 统一引用。组件和两个样式入口不再隐含切换 Inter、Roboto、JetBrains Mono 和 IBM Plex Mono。宿主需要指定品牌字体时，在根级公共字体入口设置自己的已加载字体栈；库不下载字体、不改写 html 的根字号，也不把任意祖先的 font-family 当成整库定制接口。

默认使用 sans；日志、JSON、技术 ID 与明确的品牌标题可以显式选择 mono。普通 Textarea 不因“多行输入”就天然属于代码文本。自定义代码用途应有明确的样式选择；普通内容与代码编辑的区分要在 B4 比较其现有消费者，B5 再落地最小接口，不预建新的编辑器组件。

**T2 候选默认：** 下表是 B4 的初始对照。字号用 rem，表中的 px 只表示根字号为 16px 时的结果；行高采用表中比例，无额外容器宽度输入。

| 角色／候选路径 | 字号／行高，16px 根字号下 | 字重 | 默认用途与迁移选择 |
| --- | --- | --- | --- |
| label-lg | 14/20，.875rem，10/7 | 400 | 普通 Button、Input、Dropdown、Picker；比较现有 14/16，关注中文与垂直对齐。 |
| label-md | 12/16，.75rem，4/3 | 400 | 显式紧凑按钮、短元数据；长说明优先 body-sm。 |
| body-sm（新增） | 14/20，.875rem，10/7 | 400 | 字段说明／错误、卡片摘要等辅助正文。与 label-lg 同值不意味着以后必须共同改行高。 |
| body-md（新增） | 16/24，1rem，1.5 | 400 | 普通正文、空态说明和需要阅读的设置说明；输入仍按控件用途选择 label-lg 或显式较大输入。 |
| body-lg | 18/24，1.125rem，4/3 | 400 | 突出的导语／短正文；保留已有数值作比较。 |
| title-sm | 22/28，1.375rem，14/11 | 400 | 弹层、小节与组件标题。 |
| title-lg（新增） | 28/36，1.75rem，9/7 | 400 | 普通页面标题，回应 peerList 的实际需求。 |
| headline-lg | 36/48，2.25rem，4/3 | 400 | 醒目的页面主标题；容器变窄先换行，不自动降字号。 |

比例表达允许在实现时用足够精度的无量纲数或既有编译计算，不需要新公式系统。B4 如发现字体回退导致阅读或对齐问题，先比较该角色的行高；不能为了保住固定控件高度而全局缩字。

`label-sm` 的 10/14 不再是普通信息的推荐默认。它的旧公开入口需要迁移记录；时间、状态、加载提示和 Switch 标签先试 label-md。小尺寸中的必要内容放不下时，应让几何增长或选择合适尺寸，不能靠恢复 10px 保住演示外观。是否保留一个明确用途的微型样式，由 B4 的实际场景决定，不能因此新增没有用途的角色。

**T3 决定：** 字体角色共同控制字号、行高、字重和字距；默认 sans/mono 选择独立于大小角色。常规字距候选为 0，特殊品牌 tracking 由实际标题样式明确拥有。underline 是显式装饰；命名为 underlined 的旧入口若仍提供就必须兑现装饰。Sass 与 Uno 对同一选择输出相同的显式属性，包括必要的零字距和 none 装饰重置，防止嵌套继承偶然改变结果。现有 mono 参数与 `*-mono` 旧名应收敛到同一规则；不把错误的 `apply-font('title', 'lg')` 解释成新语法。

**T4 决定：** 标签和错误信息允许按内容增加高度；单行输入保留原生单行编辑及必要的内部滚动，不能要求输入值像段落一样换行。按钮普通文本可换行；代码／不可断内容采用适合其用途的局部滚动或折行。是否显示省略号需要提供完整内容的访问方式，不能作为所有溢出的默认处理。Form 的列数及显式 row/col 模式由宿主决定，组件不因推测 viewport 自动改写调用者选择。

## S：空间、图标与控件几何

**S1 决定：** 保留 4/8/16/32/56 的基础空间尺度，默认静态；它们表达整体节奏，未承诺都随根字号或容器变化。语义上必须跟随文字的关系可以在组件中使用 em，页面留白可以由宿主随容器变化，两者都不创建全局缩放系数。

| 关系 | B4 的初始候选 | 依赖与边界／维护者 |
| --- | --- | --- |
| 标签→输入→错误 | 标签和输入间保留 4px 起点；错误前保留 4px，采用 body-sm；比较随文字的 .25em | 字段负责排布；标签、说明可增加高度，不以固定行高容器裁切。 |
| 同一表单字段组 | 默认 16px 间距 | Form 拥有；宿主可以按公开尺度调整，不能由不相关的按钮尺寸变化联动。 |
| 普通输入／下拉／Picker | 保留 36px 作为最小高度基线，内部有真实上下留白；比较固定留白与 .25em 的上下留白 | 随字体／内容需要增长；文字滚动和弹层列表分别处理。36px 是起点，不是不可超过的高度。 |
| 普通按钮 | md 最小高度以 36px 与控件对齐；上下 .5em、左右 16px 作为候选，sm 比较现有紧凑规格 | 随标签增长，保留尺寸 prop 的意义；如果新几何没有改善且更难对齐，采用更简单的留白。 |
| 按钮图标与文字 | .5em 间距候选；图形比较现有 glyph 刻度与 1em | 图形可以跟随文字，点击区域由按钮维护；当前 size.icon 与 iconfont 不是同一角色。 |
| 图标按钮／分页／Switch | 保留现有 size prop 与几何作对照；Switch 的文字、滑块宽度和位移共同复核 | 几何关系留在组件，不能只改一个高度 Token 而假设所有宽度与位移都会正确更新。 |
| 页面留白 | 先保留宿主现有规则；在侧栏场景比较固定 16/32px 与有界容器规则 | 页面拥有。仅在内容空间确有改善时选择动态方案；不能用 viewport 代替未定义的宿主容器。 |
| 图像／长列表／代码区域 | 尊重媒体比例或有界滚动区域 | 不把文字控件的最小高度政策套到内容视口，不把全部 px 替换为 rem。 |

**S2 决定：** radius、阴影与断点先保留当前设计。圆角 full 表达全圆意图，断点用于构建布局条件，阴影是整体效果；不承诺它们与文字成比例。Loading 图形与运动参数保留独立的局部责任，不能借“统一 opacity”改变所有状态表现。

## C：前景背景配对与状态优先级

**C1 决定：** 普通工作表面使用 text.base，次要信息使用可读的 text.subtle；text.muted 的实际普通文本用法归入次要前景。强动作和选中项使用 surface.primary＋text.on-primary，危险动作使用 surface.danger＋text.on-danger。这两组 on-* 分别由现有 text.primary 和 text.danger-on 澄清而来；普通表面标题不得使用反色前景。

选中项的次要描述也必须使用适配该选中表面的前景；初始候选与主要文字使用同一个 on-primary，再用字号或排布区分。只有确有视觉收益且所有合法配对可读时才增加 on-primary-subtle。surface.muted 保留迁移记录，不把一个尚无明确使用责任的第三表面推广给新代码。

**C2 决定与候选值：** 保留现有中性／品牌方向，先调整已确认的配对缺口。以下值用于 B4，而非已批准的视觉发布结果。

| 角色 | 浅色候选 | 深色候选 | 依据 |
| --- | --- | --- | --- |
| text.subtle／旧 muted 的普通文本 | 保留 #5e5e5e | 保留 #c6c6c6 | 当前普通表面上的对比度分别约 6.48 和 5.44。 |
| border.base，必要控件边界 | #777777（neutral.50） | #ababab（neutral.70） | 在现有浅色 subtle 表面约 4.25，在深色 base 约 4.05；实际必要边界与焦点分别验收。 |
| border.subtle，装饰分隔 | 保留 #c6c6c6 | 保留 #5e5e5e | 不承担辨认控件的唯一线索；旧 border.muted 按用途归并。 |
| border.strong，焦点／强调 | 保留 #070707 | 保留 #c6c6c6 | 焦点要有实际可见的轮廓，不能仅给一个 border:none 的内部输入换色。 |
| surface.danger-hover | #92001e（danger.30） | #a80324（danger.35） | 保持 on-danger 的对比度；B4 再判断状态区分和视觉方向。 |
| surface.base-hover | 保留 #eeeeee | #5e5e5e（neutral.40） | 深色候选避免与当前 base 完全同值，检查键盘高亮与选中态。 |
| feedback.error | 保留 #b9192f | #ffb3b1（danger.80） | 深色 base 上约 5.46；不能把在 subtle 上通过推广到所有表面。 |
| feedback.success（新增） | #176b39 | #75d69a | Job／连接状态的文字需求；base 上约 6.57／5.24。 |
| feedback.warning（新增） | #7a4b00 | #ffd27a | 等待／警告状态文字；base 上约 7.41／6.53。 |
| feedback.info（新增） | #005c8a | #8bceff | 运行／信息状态文字；base 上约 7.25／5.47。 |

新反馈前景先直接作为主题语义值，不为其虚构完整 primitive 色阶。状态容器默认用 surface.subtle；现有下游请求的 success.surface/danger.surface/light 先用这个组合验证，需要额外色彩容器时再给出具体理由。错误／成功的含义仍由文字或图形表达，不能只用色相传递。

**C3 决定：** normal 是基本配对；selected 改变基本配对，hover/pressed 在该配对内变化；focus 独立显示，不被 selected 或 error 覆盖。disabled/pending 停止交互性的 hover/pressed 反馈，pending 另外呈现忙碌状态。error 可以保留错误边界，同时用独立轮廓保留键盘焦点。原生焦点表现符合要求时可以保留。每个组件只实现适用状态，不枚举没有含义的组合。

Button 的整体 opacity 不再作为所有动作主题的统一 hover 规则；颜色合成必须针对其实际前景背景检查。Switch 保留单色 comp 角色与位置／文字状态，不强制随 primary 主题值变化。公共遮罩候选为 `color.overlay.scrim`，保留黑色 .5 的初始值，供 Popup 与 Scrim 共同使用并保留 alpha；Image 的反色标题需要自己有明确的深色底板或经验证的遮罩组合，不能假设白字在任意半透明遮罩和图片上都可读。

颜色阈值采用 [文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) 与 [必要非文本线索](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) 的适用条件。没有“任意颜色都保证适配任意背景”的承诺。B3 的静态计算只证明列出的不透明组合，B4 负责真实合成、主题和状态。

## O：维护责任、覆盖与求值

**O1 决定：** Git 中经评审的 `inkcre.tokens.json` 是发布的规范源，Figma 是设计值的编辑和提议入口，Web 局部响应规则由组件或宿主 CSS 维护。设计者与工程维护者通过同一变更评审决定角色和默认值；不要求响应公式都进入 Figma，也不另存一套人工同步的规范源。

导入的目标契约是“更新已有角色的候选值”，而非“来一个导出就重建公开 API”。B5 采用受限的已知路径更新：保留仓库维护的描述与导出未包含的角色；路径新增／删除、类型或 alias 关系改变需明确的契约迁移，不能由缺少某个节点推断删除。输入描述与规范源冲突应报告，不能默默覆盖；非法值在写入前拒绝。这里只需要针对现有 Token 结构的值更新，不建立通用 JSON 合并框架。

先取消无条件推断 patch 的发布分类。导入可以准备候选 PR，但 Changeset 级别由维护者显式声明，并接受既有检查和评审；自动导入成功不代表视觉兼容。B3 未连接实际 Figma 文件或修改发送端，B5 须以真实导出 payload 验证这个边界，缺少发送端信息时不能声称端到端更新已交付。

**O2 候选公开覆盖表：** 以下限定 B4/B5 要兑现的传播关系，不把技术上能修改任意 CSS 属性等同于库承诺支持的配置。

| 入口／作用域 | 允许的覆盖及优先级 | 输出与传播 |
| --- | --- | --- |
| html 的 data-theme | light/dark 显式选择优先；system／省略跟随系统 | 保留 B1/B2 契约，CSS 与所有颜色工具类一致，Teleport 到 body 的浮层也取根主题。 |
| html 上的 sys 语义颜色变量 | 按合法配对覆盖；需要分主题时给对应主题定义。根节点显式内联值优先，应用样式覆盖需采用匹配的主题选择器并在库后加载 | Sass helper 和 Uno 颜色均读取运行时变量；不能承诺只改背景而任何旧前景都仍合适。 |
| html 上的 sys.typo.family 与 sys.font 角色属性 | 指定字体栈或完整相关字体属性；根字号由宿主／用户拥有 | 两个入口保留相同变量依赖。默认 rem 字号响应根字号，比例行高响应角色字号；修改一个角色不隐含修改另一个同值角色。 |
| html 上的历史 sys.space、sys.radius | 允许有意调整共享尺度；必须接受使用该尺度的全部位置变化 | 将现有通用 CSS/Sass 与 Uno 对应工具统一为变量读取，修正 p-md 的传播差异。这是显式调整共享节奏，不是自动密度算法；组件的局部 em 关系只响应自己声明的字体依赖。 |
| html 上的现有 Switch comp 三个颜色 | 按 track、handle、label 的结构成组检查 | 仅影响 Switch；不强制响应不相关的 sys.primary 覆盖。 |
| 组件 props 与实际渲染元素 class/style | size 等公开 props 仍有效；局部 CSS 负责实例或宿主布局 | 不传播成全局主题。局部祖先的变量不会自动穿过 Teleport，暂不提供子树多主题／密度上下文。 |
| ref maps、断点、一般 size／icon／elevation 配置 | 维护者在构建源中修改并检查实际消费 | 编译配置可以是常量。保留旧 CSS 输出的兼容记录，但不新增任意 primitive 在运行期自动改写整条依赖链的承诺。 |

半透明颜色和组合值要保持信息；Sass 静态 map 与 CSS 运行入口的求值时机可以不同，但文档必须区分。B4 以颜色、字体和一个空间覆盖为代表检查传播，不用全变量快照证明所有语义成立。
